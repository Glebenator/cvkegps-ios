# GPS Comet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the position accuracy and the direction of travel as a gradient comet on the rim of the speed circle, and remove the accuracy bar from the Speed tab.

**Architecture:** A pure mapping in `CVKEGPSCore` turns the current `GpsReading`, the live status, and the phone heading into a `GpsComet` value (or `nil`). `LocationService` gets compass updates on its existing `CLLocationManager`, because Core Location gives a valid `trueHeading` only on a manager that also runs location updates. A SwiftUI `SpeedComet` view draws the value behind `SpeedDial`.

**Tech Stack:** Swift 6, SwiftUI (iOS 26), Core Location, XCTest, XcodeGen.

**Spec:** `docs/superpowers/specs/2026-11-08-gps-comet-design.md`

## Global Constraints

- iOS 26.0 or later. Swift 6 language mode: new Core types are `Sendable`.
- No new dependencies.
- Measurements stay in SI units (metres, radians). Convert only for display.
- Visible and spoken text uses `String(localized:)` or `Text` literals. The String Catalog fills itself at build time; do not edit `Localizable.xcstrings` by hand.
- Do not log headings or coordinates.
- No continuous animation: no timer, no repeating animation, no `TimelineView`.
- The compass runs only while the Speed tab is visible and the app is active.
- Documentation uses ASD-STE100 Simplified Technical English.
- Git stays local. Do not push.
- Build: `xcodegen generate`, then `xcodebuild build -project CVKEGPS.xcodeproj -scheme CVKEGPS -destination "id=F61D17D5-A0D3-48FF-8DA3-BFD7C05C8BD3" -derivedDataPath artifacts/DerivedData CODE_SIGNING_ALLOWED=NO`.
- Core tests: `cd CVKEGPSCore && swift test`.

## Review Focus

1. Direction across north: travel 350°, heading 10° must point at 340° on the screen, not at −20° or a wrap error. (Task 1 test.)
2. The 50 m edge: 50.0 m shows the comet; 50.1 m, a negative, or a non-finite accuracy hides it. (Task 1 test.)
3. Slow movement: a valid course at 0.9 m/s must rest, not point. (Task 1 test.)
4. The 30° compass edge: heading accuracy 30° points; 30.1° rests. (Task 1 test.)
5. Landscape: the comet must point ahead with the phone turned. `headingOrientation` must follow the interface orientation, with UIKit's left/right inversion. (Task 2 mapping; real-iPhone check in Task 5.)

## Deviation from the spec

- The spec puts the comet state in an accessibility element `gps_comet` for UI tests, and also hides the comet from VoiceOver. A hidden element is not visible to XCUITest, so the two conflict. This plan keeps the comet hidden from VoiceOver. Unit tests cover the states, and the UI flow screenshots show them.
- The spec suggests a separate heading protocol. This plan adds the compass to `LocationService`, which is already the app's location interface (`RecordingLocationSource`), because `trueHeading` needs the same manager. The Core type `PhoneHeading` keeps Core Location types out of the mapping.

### Task 1: Comet mapping in Core

**Files:**
- Create: `CVKEGPSCore/Sources/CVKEGPSCore/GpsComet.swift`
- Test: `CVKEGPSCore/Tests/CVKEGPSCoreTests/GpsCometTests.swift`

**Interfaces:**
- Produces:
  - `public enum PhoneHeading: Hashable, Sendable { case unavailable; case current(trueRadians: Double, accuracyRadians: Double) }`
  - `public struct GpsComet: Hashable, Sendable` with `public var glow: Double` (0 = ±3 m or better, 1 = ±50 m) and `public var direction: Direction`.
  - `public enum GpsComet.Direction: Hashable, Sendable { case resting; case pointing(screenRadians: Double, focus: Double) }` — `screenRadians` is clockwise from the top of the screen, in `[0, 2π)`; `focus` is 14 (sure) to 2 (unsure).
  - `public static func GpsComet.make(reading: GpsReading?, live: Bool, heading: PhoneHeading) -> GpsComet?`
  - `extension GpsReading { public var travelRadians: Double? }` — `bearingRadians` when it is finite and `speedMetersPerSecond >= 1`, else `nil`.
  - `public enum CompassPoint: CaseIterable, Sendable { case north, northEast, east, southEast, south, southWest, west, northWest; public init(radians: Double) }` — 45° sectors centred on each point.

- [ ] **Step 1: Write the failing tests**

`GpsCometTests` with a helper `reading(accuracy: Double?, speed: Double? = 10, bearingDegrees: Double? = 90, bearingAccuracyDegrees: Double? = 5) -> GpsReading` and `heading(_ degrees: Double, accuracy: Double = 5) -> PhoneHeading`. Tests:

- `testHiddenWhenNotLive`: `make(reading: reading(accuracy: 3), live: false, heading: .unavailable)` is `nil`.
- `testHiddenWithoutReading`: `make(reading: nil, live: true, …)` is `nil`.
- `testAccuracyLimit`: accuracy 50.0 is not `nil`; 50.1, −1, `.infinity`, `.nan`, and `nil` are `nil`.
- `testGlowScale`: accuracy 3 → glow 0; 1 → 0; 50 → 1; √(3·50) ≈ 12.25 → 0.5 (accuracy 0.001).
- `testRestsWithoutCompass`: heading `.unavailable`, speed 10 → `.resting`.
- `testRestsWhenSlow`: speed 0.9, heading current → `.resting`; speed 1.0 → `.pointing`.
- `testRestsWithoutCourse`: `bearingDegrees: nil` → `.resting`.
- `testCompassAccuracyEdge`: heading accuracy 30° → `.pointing`; 30.1° → `.resting`; −1° → `.resting`.
- `testDirectionRelativeToPhone`: travel 90°, heading 0° → 90°; travel 350°, heading 10° → 340°; travel 10°, heading 350° → 20°; travel 0°, heading 0° → 0° (all in radians, accuracy 1e-9, result in `[0, 2π)`).
- `testFocus`: course accuracy 1° and heading accuracy 1° → focus 14 (combined √2° is below 2°); course 45°, heading 0° → focus 2; course nil and heading 0° → combined 20°, focus = 14 − 12 × ln(10)/ln(22.5) (accuracy 0.001).
- `testCompassPoints`: 0° → `.north`; 22.4° → `.north`; 22.6° → `.northEast`; 359° → `.north`; 180° → `.south`; 270° → `.west`; −90° (as radians) → `.west`.

- [ ] **Step 2: Run the tests and make sure they fail**

Run: `cd CVKEGPSCore && swift test --filter GpsCometTests`
Expected: build error, "cannot find 'GpsComet' in scope".

- [ ] **Step 3: Implement `GpsComet.swift`**

Values from the spec: glow = clamp((ln a − ln 3) / (ln 50 − ln 3), 0, 1); the limit is `UsabilityLimits.maxHorizontalErrorMeters` (50). Pointing needs `travelRadians`, `.current` heading with 0 ≤ accuracy ≤ 30° (π/6). Screen angle = (travel − heading) normalised into [0, 2π). Combined uncertainty u = √(course² + heading²) in degrees, course = 20° when `bearingAccuracyRadians` is `nil`; s = clamp((ln u − ln 2) / (ln 45 − ln 2), 0, 1); focus = 14 − 12·s.

Run: `cd CVKEGPSCore && swift test`
Expected: all tests pass, including the existing suites.

### Task 2: Compass in LocationService

**Files:**
- Modify: `CVKEGPS/Location/LocationService.swift`
- Modify: `CVKEGPS/Screens/SpeedView.swift` (lifecycle only, near the existing `.onAppear`/`.onDisappear` at lines 61–62)

**Interfaces:**
- Consumes: `PhoneHeading` (Task 1).
- Produces on `LocationService`:
  - `private(set) var heading: PhoneHeading = .unavailable` (observable)
  - `func compass(_ on: Bool)` — starts or stops heading updates. Stopping sets `heading = .unavailable`.
  - `func setCompassOrientation(_ orientation: UIInterfaceOrientation)`

- [ ] **Step 1: Implement the compass**

- In `compass(true)`: do nothing if `!CLLocationManager.headingAvailable()` (the simulator). Else set `manager.headingFilter = 1` and call `manager.startUpdatingHeading()`.
- `locationManager(_:didUpdateHeading:)`: `heading = newHeading.headingAccuracy >= 0 && newHeading.trueHeading >= 0 ? .current(trueRadians: trueHeading·π/180, accuracyRadians: headingAccuracy·π/180) : .unavailable`. No time-based expiry (spec: the 1° filter sends nothing while the heading is steady).
- `locationManager(_:didFailWithError:)`: when the error is `CLError.headingFailure`, set `heading = .unavailable`. Keep the existing handling of other errors.
- `locationManagerShouldDisplayHeadingCalibration(_:)` returns `false`.
- `setCompassOrientation`: `.portrait → .portrait`, `.portraitUpsideDown → .portraitUpsideDown`, `.landscapeLeft → .landscapeRight`, `.landscapeRight → .landscapeLeft` (UIKit's interface and device orientations are inverted in landscape), anything else → `.portrait`. Assign to `manager.headingOrientation`.
- Extend the delegate's nonisolated callbacks the same way as the existing location callbacks (hop to the main actor).

- [ ] **Step 2: Drive it from the Speed tab**

In `SpeedView`, read `@Environment(\.scenePhase)`. The compass is on when the view is shown and `scenePhase == .active`: call `model.location.compass(_:)` from `.onAppear`, `.onDisappear`, and `.onChange(of: scenePhase)`. Call `setCompassOrientation` from `.onAppear` and when the view's size changes between portrait and landscape (`onGeometryChange(for: Bool.self) { $0.size.width > $0.size.height }`), using `(UIApplication.shared.connectedScenes.first as? UIWindowScene)?.interfaceOrientation`.

Run the build command from Global Constraints.
Expected: `** BUILD SUCCEEDED **`, with no new warnings in `LocationService.swift` or `SpeedView.swift`.

### Task 3: Comet drawing on the speed circle

**Files:**
- Create: `CVKEGPS/Screens/SpeedComet.swift`
- Modify: `CVKEGPS/Screens/SpeedView.swift` (`SpeedDial`, and its three call sites at lines 17, 33, 41)

**Interfaces:**
- Consumes: `GpsComet.make(reading:live:heading:)` (Task 1), `LocationService.heading` (Task 2).
- Produces:
  - `struct SpeedComet: View { var comet: GpsComet; var diameter: CGFloat }` and `static let reach: CGFloat = 24` on `SpeedComet`.
  - `SpeedDial(speed: Double?, comet: GpsComet?)`.

- [ ] **Step 1: Implement `SpeedComet`**

- Colours: `Palette.accent` at the pointing direction into `Palette.gradientEnd`. Mix per stop with `Color.mix(with:by:)`, weight d = ((1 + cos(θ − toward)) / 2)^focus. Use 72 stops in an `AngularGradient` that starts at the top (−90°).
- `.resting`: toward = 315° (top left, as the icon), focus = 1.5.
- Rim: a 2.5 pt stroke on the circle edge, opacity 0.95.
- Glow: a blurred stroke just outside the rim. Its width, blur, and opacity grow with `comet.glow`: about 2× wider and 3× softer at glow 1 than at glow 0, opacity 0.5 → 0.3. Everything, blur included, stays within `SpeedComet.reach` (24 pt) outside the circle.
- Increase Contrast (`colorSchemeContrast == .increased`): rim opacity 1, glow opacity × 0.6.
- `.accessibilityHidden(true)`.
- `.animation(.easeOut(duration: 0.3), value: comet)`, or no animation when `accessibilityReduceMotion` is true.

- [ ] **Step 2: Put it in `SpeedDial`**

- New diameter: `min(min(geometry.size.width, geometry.size.height) − 2 × SpeedComet.reach, 320)`. In portrait on an iPhone this stays 320; it shrinks only in the 240 pt accessibility frame and in the wide layout.
- Draw `SpeedComet` behind the existing material circle when `comet != nil`.
- At the three call sites pass `comet: GpsComet.make(reading: model.speed.reading, live: model.speed.status == .live, heading: model.location.heading)`.

- [ ] **Step 3: Build and look at it**

Run the build command, install and launch the app on the simulator, and run `xcrun simctl location F61D17D5-A0D3-48FF-8DA3-BFD7C05C8BD3 run "Freeway Drive"`.
Expected: the resting comet (blue at the top left) shows on the rim while the drive runs (the simulator has no compass). After `xcrun simctl location … clear` and 10 s, the comet goes away with the speed.
